# 役割

配布された不完全な `CLAUDE.md` を、**このプロジェクトの実物を読んで**完成させる。加えてメモリの初期ファイルを作る。ユーザーに一から書かせない。

# 手順（順に実行・勝手に先へ進まない）

## 1. プロジェクトを実際に読む（推測で埋めない）

以下を**実在するものだけ**確認する。無いものは「無い」と扱う。

- `README.md` — 何を作っているか
- `package.json` / `pyproject.toml` / `Cargo.toml` / `go.mod` 等 — 技術スタックと**scriptsに書かれた実際のコマンド**
- `git log --oneline -15` — 最近何が動いているか
- ディレクトリ構成（深さ2まで）— どこに何があるか
- `.github/workflows/` `Dockerfile` `.env.example` — 触ると事故る場所の候補
- `.gitignore` — 生成物・秘密ファイルの場所

**READMEに書いてあることと、実際のファイルが食い違う場合は実物を正とする。**その食い違い自体を報告する（放置すると毎セッション混乱の種になる）。

## 2. 埋める内容を一覧で提示する（ここで必ず止まる）

`CLAUDE.md` の `<...>` を、**埋める前に**表で見せる。

| 空欄 | 埋める内容 | 根拠（どのファイルから読んだか） |
|---|---|---|

**根拠の列を必ず埋める。**根拠が書けない欄は埋めず「不明——本人に質問」と書く。推測で埋めるのは、このキットが避けようとしている失敗そのもの。

同時に、本人にしか答えられないことだけを質問する（最大3問）。調べれば分かることは聞かない。

- 「触ってはいけない場所」で、ファイルからは読めないもの（他人の担当領域・本番接続先など）
- 「事故防止」に足すべき、**過去に一度やられて困ったこと**（この行が実際に一番効く）
- 回答の言語・口調の希望

## 3. 承認を取ってから反映する

承認された分だけ `CLAUDE.md` に反映する。**空欄のまま残した箇所は `<...>` を消さずに残し**、どこが未完成かを報告する（消すと未完成が見えなくなる）。

## 4. メモリの初期化

Claude Code のメモリは**プロジェクトごとの専用ディレクトリ**に置かれる。置き場をユーザーに確認し（`/memory` で確認できる）、そこに以下を作る。

- `MEMORY.md` — 索引。1メモリ1行（`- [タイトル](ファイル名.md) — 一言`）。**索引に内容そのものを書かない**
- 最初の1件として `project` タイプのメモリを1つ作る（今のプロジェクトの現在地。手順1で読んだ内容から）

書式は同梱の `メモリの書き方.md` に従う。

## 5. 完了報告（この形で）

1. 埋めた空欄と、残した空欄
2. 作ったメモリファイル
3. 手順1で見つかったREADMEと実物の食い違い（あれば）
4. **次の使い方の案内**：セッションを開いたら `/kit-standup`、閉じる前に `/kit-handoff`

# 注意

- **このskillは1回だけ**。2回目以降は必要な箇所だけ直接編集する方が速い。
- `CLAUDE.md` を長くしすぎない。長くなるほど指示の追従は落ちる。**ただし具体的な行数の閾値は断定しない**（根拠のない数値を出さない）。判断基準＝**同じことが2回書かれていたら、それがskillへ退避させる合図**。
- 設定ファイル（package.json等）は**読むだけ**。このskillは一切変更しない。
