# 役割

セッションを終える時に、**次のセッションが「メモリ＋コミットだけ」で迷わず再開できる状態**を作る。「やったつもり」を排し、**独立した検証**で引き継ぎの穴を潰す。

会話が劣化してから慌てるのではなく、綺麗な区切りで橋を架けるのが狙い。

# いつ使うか

- セッションが長くなって別セッションへ移る時
- 大きな区切り（段階完了・スコープ確定・実装と検証の完了・方針転換）
- 「引き継ぎ」を求められた時

# 手順（順に実行・各ステップの結果を確認してから次へ）

## 1. 現在地の確定

- 「**何が完了し／何が未確認で／次の一手は何か**」を1段落に言語化する。
- `git log --oneline -8` と `git status --short` でコミット済み／未コミットを把握する。

## 2. メモリ整流（最重要）

関連するメモリを**通読**し、最新の結論で上書きする。

- 完了事項・次の一手・**入口**（主要ファイル／関数／定数／実行コマンド）を明記する
- ★**会話の前半に書いた暫定的な記述が残りやすい。**古い節と新しい結論の**矛盾を必ず解消する**
- ★**`MEMORY.md` の索引行も最新化する**——索引と詳細が食い違うと、次のセッションが**済んだ作業を再着手しかける**。これが最大の落とし穴

## 3. コミット衛生

- 成果を**意味単位でコミット**する（1コミット1目的。関係ないファイルや別作業の差分を混ぜない）
- コミットは自発的に打ってよい。**push など外向きの操作は本人の手で**行う（勝手に公開しない）

## 4. 独立監査（フレッシュアイ）

**この会話の履歴を持たない独立したエージェント**を起動し、「残された成果物（`MEMORY.md`＋各メモリ＋設計ドキュメント＋git log＋コード）**だけ**で、新しいセッションが綺麗に再開できるか」を検証させる。

検証項目：

1. メモリとコードの整合（主張されている関数・定数・挙動が実在するか。grepと構文チェックで）
2. 参照されているコミットが実在するか
3. 次の一手が矛盾なく読めるか（古い記述が残っていないか）
4. 実行コマンドが正しいか
5. 壊れたリンク・紛れ込んだゴミ

監査役の出力は**判定（yes / mostly / no）＋GAP番号リスト**（ファイル・箇所・直し方）。**監査役は何も変更しない**（報告のみ）。監査と修正を同じ役に持たせると、自分の穴が見えなくなる。

## 5. GAP修正

指摘を直す。**「索引が1世代古い」を最優先**（再着手を招くため）。
**削除が必要な場合は明示の指示を取ってから**行う（勝手に消さない）。

## 6. 橋渡しサマリ（提示する）

- **監査判定**
- **やったこと**（物語1本・簡潔に）
- **成果物のありか**（メモリ／ドキュメント／コミットハッシュ）
- **次セッションの再開手順**（読む順 → 第一手 → 着工するタスク）
- **本人の手が必要な操作**（push・削除の許可・外部設定など）を箇条書きで

# 注意

- 監査と修正は分ける（監査＝独立・検証のみ／修正＝本体）。
- 報告は結論先・簡潔に。
- **このskillは汎用**。プロジェクト固有の入口・規律は手順2で都度埋める。
