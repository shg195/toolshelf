# 役割

セッションの立ち上がりの摩擦をゼロにする。**読み取り専用**（ファイルは書き換えない）。

# 手順

## 1. 現在地の入口を特定する

メモリの `MEMORY.md` 索引を読み、**最新の状態を持つメモリ**を特定して読む。「最新はこれ」と決め打ちのファイル名を覚えない（陳腐化する）——索引の先頭側と日付で毎回判定する。

## 2. 鮮度検査（これが本題）

`git log --oneline -15`（＋直近コミットの日時と `git status --short`）を、メモリの記述と突き合わせる。

- **メモリが直近のコミット群を説明できている** → 通常モード。手順3へ。
- **コミットや未コミット変更がメモリより新しく、説明されていない** → **「前回はhandoffなしで終了した」と判定**し、次を行う：
  1. ブリーフの冒頭でその旨を宣言する（黙って推測で埋めない）
  2. git log の差分・直近変更ファイル・未コミット変更から現在地を再構成し、**【再構成・信頼度低】のタグをつけて**提示する
  3. **メモリへの追記を提案する**（5分で正を回復できる。実行は承認後）

## 3. 未処理の入力を拾う

プロジェクトに受け箱（TODO・issue・引き継ぎメモ等）があれば、未処理のものを列挙する。無ければ飛ばす。

## 4. 出力（1枚・この順・簡潔に）

- **現在地**（3行以内）
- **待ち事項**——「外部待ち／自分の手番／AIの宿題」に分ける（誰が動かないと進まないかを明示する）
- **未処理の入力**
- **今日の一手（推奨を1つだけ）**——理由を1〜2行

## 5. 出したら止まる

ブリーフを出したら指示を待つ。**勝手に作業を始めない**（メモリへの追記提案も承認後）。

# 注意

- **深追いしない。**読むのは索引が指す先だけ。全ファイル走査はこのskillの仕事ではない。目標は5分以内。
- 未達・遅れは**責めずに数字で**示す（「遅れています」ではなく「期限まで残3日・未着手」）。
- 判定できないことは「判定できない」と書く。埋めない。
