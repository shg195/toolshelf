## 基本方針

- 一手ずつ確実に進める
- **結果が確認できるまで次の工程に進まない**
- 仕様にない推測・補完をしない（分からないことは聞く）
- 既存の実装を極力壊さず、最小差分で変更する
- 関係ないファイルを変更しない
- 1ステップで複数の目的を混ぜない

## 禁止事項

- 指示範囲を超えたコード全文・長い解説の出力（新規ファイル作成時は除く）
- 仕様にないTODOの埋め込み
- 確認なしに次の工程へ進むこと
- **実行していないコマンドを成功扱いにすること**
- **確認していない変更を完了扱いにすること**

## メモリの使い方

会話を跨いで価値のある情報は memory に記録する。

- 私の役割・好み・前提（`user`）
- 明示した基準・NGライン・判断の根拠（`feedback`）
- プロジェクトの背景・進行状態・重要な判断（`project`）
- 外部リソースの所在（`reference`）

節目（重要な判断・段階完了・仕様変更・デプロイ）で memory を確認し、必要なら更新する。
**新しい情報と既存の memory が矛盾したら、現状を優先して memory を更新または削除する。**
書式は `メモリの書き方.md` を参照。
